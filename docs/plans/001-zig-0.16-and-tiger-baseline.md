# Plan 001 — Zig 0.16 migration and Tiger Style baseline

## Goal

Move zr from Zig 0.15.2 to 0.16.0 with `zig build test` and `zig build integration-test` green in
CI on 0.16.0, and land the Tiger Style floor this repo never had: a machine-checked `tidy` step,
real assertions in the hot modules, docs that match the shipped binary. Release as v1.115.0.

## Why now

Plan `001` of every realm is this migration (`citadel/docs/ROADMAP.md`, Phase 1), and the kingdom
forbids new 0.15-shaped code: 149 of zr's 227 files (66%) touch `fs`/`net`/`time`/`process`/`io`,
so waiting only enlarges the diff. zr also has an unusual Tiger Style hole — **0
`std.debug.assert` in 112.5k LOC**, 12 `catch unreachable`, a ~5,100-line `parseToml` — and a
migration rewriting most files is the cheapest moment to install rails that keep it honest. The
code items are blocked until zuda and sailor tag v3.0.0 (both `build.zig` files call the removed
`Step.Compile.linkLibC()`); the hygiene, tidy, assertion and branch items fill those cycles.

## Out of scope

- Structural debt — splitting `config/parser.zig` (8299 lines, one ~5100-line `parseToml`) and
  `exec/scheduler.zig` (3755): ROADMAP Phase 3; the tidy allowlist already records the debt.
- New features (`docs/plans/000-inherited.md` frozen until 002) and moving zr onto sigil for
  TOML/YAML (ROADMAP Phase 3, needs sigil v0.1).

## Risks

- **The probe undercounts.** 79/200 standalone-tested files failed, but the compiler stops each
  unit at its first error and 66% of the tree touches an affected API. The `fs` → `Io` batches are
  the likely overruns; each commits green alone, so a spill costs a cycle, not the plan.
- **Blocked on two upstream tags.** Nothing from item 5 on moves until zuda and sailor tag v3.0.0.
  If they slip, use 0.16's local package override against unpublished checkouts — never bump a pin
  hash first, never patch a dependency locally. zuda's pin is a `main` ref declaring 2.0.4 while
  silica pins 2.3.0, so v3.0.0 may carry drift across the ~28 files using `compat.zr_dag`.
- **Regressions hide in the integration suite.** The ~270-failure CI-red period before v1.113.1
  went unnoticed because sessions ran unit tests only; every batch runs `integration-test` first.
- **Tidy without the ratchet blocks everything**, and **GPA leak detection fails the build while
  every log line says "0 failed"** — grep test logs for `leaked` separately from `FAIL`.

## Done when

- `build.zig.zon` has `.minimum_zig_version = "0.16.0"`, `sailor` 3.0.0 and `zuda` 3.0.0 (tags).
- CI green on `main` with no `version:` pin in `ci.yml`: unit, integration, 6 cross-compile jobs.
- `zig build tidy` green in CI, and red on an injected violation.
- `grep -rn 'std\.net\.\|std\.fs\.cwd\|GeneralPurposeAllocator\|ArrayList(.*){}' src/` is empty.
- `git branch -r` lists no `wip/*`; PR #30 merged or closed with a reason; README badge matches.
- `git tag -l v1.115.0` is non-empty and the GitHub release is published.

## Version impact

**MINOR** → v1.115.0. A toolchain migration that changes public signatures is MAJOR only for a
library with consumers; zr is the tooling layer and no kingdom repo imports it, so the new
`io: Io` parameters break no downstream. CLI behaviour and `zr.toml` semantics are unchanged.
